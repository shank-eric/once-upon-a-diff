# ADR-22: dependency-cruiser is the one home for layer rules, and ESLint keeps style and side effects

Decided 11/4, built in 8553da5, with the cycle rule made an error in a0036f5 (11/5). Descriptive, of the code on main at 168b6b1. It supersedes the "Enforced by lint" bullet of [ADR-15](adr-15-layered-packages-and-protocol.md) and the boundary-lint bullet of [ADR-16](adr-16-what-the-rebuild-built.md), which made `eslint.boundaries.mjs` the source of the layer rules. [ADR-17](adr-17-host-github-and-the-end-of-shared.md) names the same file.

## Context

The layer rules lived in two places. `eslint.boundaries.mjs` held one entry per layer and region and `boundary-lint.test.ts` probed each with a violating file. `.dependency-cruiser.mjs` (added 11/4 in d4ab2cc, with knip) mirrored them over the whole import graph and added cycles, and a `layer-rules-agree` test failed when the two disagreed. Making that test pass found places where they had disagreed (85eb01a). dependency-cruiser sees the whole graph, so an import through a re-export still counts, where ESLint reads one file at a time. Keeping two files equal by a test is upkeep that decides nothing.

## Decision

- **`configs/.dependency-cruiser.mjs` is the one home** for which package, layer or region may import which, and for import cycles. `yarn depcruise` runs it over the source of every package (`yarn lint` runs ESLint and then it, and CI runs `yarn lint`). It sees the whole graph, so an import through a re-export still counts. The rules are written as named pairs (importer, imported, a comment saying why) and each says what to do instead. 50 rules on 11/5, in these groups: core's tiers and the package edges (ADR-20, ADR-21), the CLI-never-calls-the-server pair (the health check is the doctor's, no route table in the CLI or core: ADR-15, with `packages/bridge/test/cli-never-calls-server.test.ts` for what a graph can't see), the client packages and the apps over them (ADR-15), the board's and the panel's regions, what ships to a browser (no Node built-ins), the contracts package (imports only itself, the domain and valibot) and the domain (imports nothing), and the test kit (dev only: nothing that ships imports it).
- **ESLint keeps style and the side-effect rules.** `configs/eslint.side-effects.mjs` says only an adapter runs a program, writes a file or reaches the network (child processes, the network, threads and `vm`, `node:fs` writes, module loaders, `fetch`, `process.kill`), with the HTTP app allowed `node:http` to listen. It is about what a file calls, which the import graph can't show, so it stays in ESLint.
- **Cycles are errors.** `no-circular` was a warning while 19 cycles existed. a0036f5 broke the last eight, each a value import of a small pure helper out of a module that also imports a type back into the loop, and made the rule an error. Type-only edges are ignored, so a type may point back.
- **A test proves every rule can fire.** `packages/bridge/test/layer-rules.test.ts` builds a temp tree shaped like the repo's packages (`core/src/<tier>/<folder>`, `server`, `cli`, `bridge`, and each client package), writes one probe file per import, runs the repo's config over it, and requires each forbidden probe to trip its own rule and nothing else, and each allowed probe (the import the rule permits beside it) to trip nothing. Every rule has at least one forbidden probe: the core, package and tier rules one by one, the cross-package rules as a matrix of importer by imported package, and the region, contracts, domain, test-kit, URL-spelling and unresolved-import rules each on their own. A second test fails when a rule in the config has no probe, or a probe names a rule the config no longer has, so a new rule cannot land without one. A rule whose path stops matching (a renamed tier, a moved package, a broken `from` or `to`) goes quiet, and the probe fails. `packages/bridge/test/side-effects-lint.test.ts` does the same for the ESLint side-effect rules.
- **Source only.** Tests, scripts and config cross packages on purpose, so they are not cruised. The browser imports its modules by URL (`/assets/panel/shell/overlay.ts`), so `configs/tsconfig.depcruise.json` maps each URL back to its file with the same `paths` as the pages' tsconfig (the pages' own files listed one by one, so the vendored `/assets/vendor/preact.mjs` resolves to nothing and the one Preact stays `/assets/preact.mjs`), and an import that resolves to nothing is an error.
- **Dead code is knip's job.** `yarn knip` (`configs/knip.jsonc`) lists the entries of each package. It is not part of `yarn lint`.
- **Agents are told not to work around it.** `AGENTS.md` says the config is the one home: if a layer really has to move, change its rules there.

## Consequences

- One file says what may import what. A new package or layer is a rule there and a probe in `layer-rules.test.ts`, which fails until the rule has one.
- A change to the core layout (ADR-20's split) is an edit to this file and to the probes in `layer-rules.test.ts`.
- The rules are only as good as their paths. A tier renamed without its rule leaves it matching nothing. Every rule has a probe, so the test catches that; a probe only covers the paths it imports through, so a rule with several importers or targets has a probe for each.
- The side-effect rules are a second small place, in ESLint. A file that calls a program through a module the rule doesn't name gets past it (the lint missed `promises`, `createRequire` and `globalThis.fetch` once: ADR-16).
