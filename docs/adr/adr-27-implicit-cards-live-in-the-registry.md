# ADR-27: Implicit cards live in the registry: work that did not start in the backlog is its own card, with no row in backlog.jsonl

Decided 11/6 by Eric (the plan's questions 1, 2 and 5, notes/research `2026-11-06-ou-implicit-cards-plan.md`), built in the commit that adds this file, and descriptive of the code on main at that commit. It finishes the implicit-card half of the follow-up (a) in [ADR-25](adr-25-the-card-owns-its-runs.md) (Not built here); the editors half is built there.

## Context

ADR-25 made the card the key: a run names its card, and the board reads the card's column from its runs. 170 of 578 starts in the store (11/3 to 11/6) had no card (helpers 91, critics 26, researchers 26, authors 23, editors 4), across 137 distinct `sid:name`. The draft closed that gap with an implicit card: `agent start` with no `--card` adds a card to `backlog.jsonl` (`add` with `implicit: true`, closed by a `done by implicit`). Eric chose on 11/6 that runs stay in `agents.jsonl`, with `card` a required, checked key, and not events in `backlog.jsonl`. Each of his reasons holds for implicit adds: one `agent start` would be two files with no atomicity, `backlog.jsonl` (1,576 rows) has no incremental reader and would grow by about 57 cards a day (about 270 rows with their `done`s in 2.4 days), and `records/` cannot write a file of the tier above it.

## Decision

- **An implicit card is its first run.** `agent start NAME` with no `--card` (and no earlier run of the same `sid:name` to carry one over) mints an id, `ic_` and a fresh suffix (`newImplicitCardId`, `implicitCardId` in `domain/src/ids.ts`), and writes it as the `card` of its one start row. No other file is written. That row is the card: its task is the title (cut at 80 characters), its repo the card's, its sid the claim, and a later run on the card may fill a branch the first had none of (`implicitCards`, `state/src/records/agents/implicit.ts`; `implicitItems`, `queues/backlog/implicit.ts`, shapes them as items marked `implicit`).
- **One id regex.** `BACKLOG_ID_RE` is `(bl|ic)_...`, since an adopted card keeps its id. A typed `--card ic_...` is accepted only when an earlier start row carries it, so a typo still fails with "no backlog card". The write checks (`contracts/src/files/strict.ts`) take the same regex, so an `ic_` start row is written strictly like any other.
- **Reuse.** A restart of the same `sid:name` stays on its earlier run's card, as a fix round does (ADR-25), with no time window: a follow-up on the same topic goes to the same named agent, and `--new-card` starts a fresh card. A critic or storyteller of ad-hoc work passes `--card` with the id `agent start` printed as a third word, and only an implicit card's start prints one.
- **Who mints.** Authors, helpers and researchers (a plain `--kind author` too). Not a critic, fixer or storyteller (Eric, Q2): they work on a card that exists, and a critic that minted its own card is the 11/5 miss that ADR-25 closed. A standing helper and an editor have no card. `--role author` with neither a card to carry over nor a `--branch` is refused: the branch is what the card is.
- **No branch, no critic.** A critic or a storyteller on a card with no branch (an implicit card or a backlog one) is refused: there is nothing to read.
- **Adopt.** `backlog adopt ID [--title]` writes the one `add` event, under the same id (`BacklogStore.add` takes an `id`), with the title, repo, branch and the whole task as its note. When the card has a branch it also writes the `start`, as `claim --branch` does, so the card reads as started: no Assign while its author runs, and a built card on a branch reaches Ready instead of leaving the board. A card with no branch stays open, and the Assign button is skipped for any card whose runs are working it. Its runs already name the card, so from then on the board reads them by `cardPhase` and it is a backlog card. A card is looked up in the backlog first, then in the registry's runs: an adopted card that was dropped or landed takes no more runs, and a made-up id takes none either.
- **Where it shows.** `backlog list` leaves implicit cards out. `--implicit` lists those with a run open and not stale (with `--all`, every one), `--all` adds them, marked `implicit`, and `show ID` prints one. Every other verb on an `ic_` id says to adopt it first. On the board an implicit card is the agent card there already was, `agent:<sid>:<name>` of its first run, so Finish, lanes and the finished timers do not change; its other runs (a critic of it) are views on that card instead of cards of their own, and the card is in the first run's column unless that run is over and another is going. If the first run's card is gone (cleared, or past its timer) the next run is the card. Finish on the card clears the card's other finished runs too (`finishAgent`), so a critic does not come back as a card of its own.
- **Closing is derived, never written.** No `done` row: the agent card leaves the board after `board_finished_wait_minutes`, or on Finish, as it did, and the card is "live" for `list --implicit` while a run is open. A landing does not close it (Eric, Q5): it leaves by pending-review, the merge, Finish or the timer, as a cardless author did. Adopting is how to make landing track it.
- **Only a registry made with the backlog's lookup mints** (the CLI's). A registry made without one only records, as in ADR-25, so the worlds and state tests write runs as before and every earlier golden is unchanged.

## Not changed

Old cardless rows (the 170) are not rewritten and are not given cards: they keep the placement they had until the flip. The flip (ADR-25 (b)) now only has to refuse the typed flags, since no author is left without a card. `once-upon doctor` does not call a run on an `ic_` id "not a card". Implicit cards from another session are not hidden from a `--card` passed on purpose.
